# 接口方法论（api-methodology）

> 本文档仅描述**方法论原则**，不含任何真实接口地址、请求参数或代码。实现时请按目标平台官方文档与公开接口现场核对。

## 一、读取（盘点）

### 分页铁律

- **必须循环"是否有更多"标记**，不能用"本页返回条数不足一页"作为结束条件——第 1 页就可能不满但仍有下一页，提前停会漏读约 5% 的数据。
- 读取模板（方法论）：循环页码 → 请求一页 → 解析 → 保存本页记录 → 检查"是否有更多" → 有则下一页并限速，无则结束。

### 字段与失效视频

- 每条视频记录应包含：所属收藏夹、视频标识、视频编号、类型、标题、UP 主、失效标记、时长、收藏时间、封面、简介。
- **失效标记非 0 即已失效视频**（标题常为"已失效视频"）→ 归入 DEAD，执行阶段取消收藏。
- 分类匹配文本只用**标题 + UP 主名**；不要拼简介（简介噪声会导致误分类）。

## 二、写入（POST 才有用）

- 所有写接口 GET 一律无效，必须 POST。
- 新建收藏夹、删除收藏夹、移动视频、取消收藏、改收藏夹名均需 POST + CSRF 令牌。

### 批量操作三铁律（防静默失败，血泪教训）

1. **批量参数绝不能重复参数名**——服务端只认第一个，其余静默丢弃且返回成功码（曾导致大量操作表面成功、实际约 1/3 没生效）。
2. **类型后缀必须取记录的 type 字段**（普通稿件、剧集条目等类型不同，写错同样静默无效）。
3. **成功码 ≠ 生效**：即便批量接口返回成功，偶发单条静默失败。执行完必须把源收藏夹用列表接口**抽干复核**（循环到无更多），以抽干结果为准决定是否补跑。

### 其他要点

- **条数是服务端缓存**，严重滞后（清空后仍显示很多）。**判断收藏夹是否清空只信抽干结果，不信条数**。
- 删除收藏夹的参数形态（复数）与新建不同——以平台当前接口文档为准，写错会返回参数错误。
- **新增收藏（resource/deal 类接口）有签名坑**：手动重放页面请求可能被拒（新前端带签名头）。批量收藏走页面 UI 点击最稳；移动/取消收藏类接口通常不受影响。
- **CSRF 令牌**：值等于当前 cookie 中的 CSRF 字段，且**必须现读现用**（会轮换，旧值导致校验失败）。
- 移动的重复语义：目标夹已有该视频时，移动会把源夹副本移除、目标夹保留已有条目——可用于清理同一视频在多个收藏夹里的重复副本。

## 三、执行环境注意事项

- **写操作必须走浏览器页面上下文**：浏览器自动携带含 HttpOnly 的登录 cookie，脱离浏览器直接发请求缺登录态会返回"未登录"。
- **先做最小写操作冒烟测试**（如删除一个已确认空的收藏夹），成功码且抽干为 0 → 写接口链路通，再批量。
- **限速**：每请求间隔 1.0~1.6 秒 + 每 40 请求额外暂停 3 秒，可全程不触发风控。
- **断点续传**：每批把成功的视频标识追加进日志，重跑跳过已成功项。

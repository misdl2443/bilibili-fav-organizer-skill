# GUI 兜底流程方法论（gui-flow）

> 适用场景：接口批量写入被风控卡死时的兜底。在收藏夹页面（视频网格视图）逐个处理视频。
> **本文档只讲方法论，不含具体页面选择器**——页面元素随平台改版变化，操作前先对页面做快照，现场核对"更多选项按钮 / 下拉菜单项 / 弹框单选与确定按钮"的实际位置与标识。

## 单个视频的处理流程

1. 打开（悬停或点击）**第一个**视频的"更多选项"按钮，等待下拉菜单出现。
2. 判断：
   - **已失效视频** → 点"取消收藏"，本条结束；
   - 正常视频 → 点"移动至"，等待弹框出现。
3. 按该视频的**标题**判断最接近的分类，在弹框中选中对应收藏夹。
4. 点"确定"，等待该视频从列表消失。

## 批量模式（位置刷新，关键认知）

- **处理完第 1 个视频后，第 2 个视频会顶到第一位**。因此处理页面上第 N 个视频时，第一步仍然是"打开**第一个**视频的更多选项按钮"，只是第 3 步要按**第 N 个视频的标题**选分类。
- 收到一页后，**一次性生成该页所有视频的全部操作序列**，然后统一执行，避免反复请求页面：
  - 页面快照里包含每个视频的标题和全部收藏夹类别的标识，生成操作所需的信息都在页面里。
  - 操作序列形如：`打开第一个的更多选项` / `选择目标收藏夹`。
- 执行完该页全部操作后，**重新获取页面**（刷新或重进收藏夹），重复以上步骤，直到重新获取的页面再无视频。
- 已失效视频被取消收藏后同样会使后一个视频顶上来，规则相同。

## 节奏与验证（兼顾风控）

- 每个动作之间等待 1~2 秒：等 DOM 刷新，同时天然避免风控。
- 每个视频完成后验证：下拉菜单已消失、弹框已关闭、该视频不再出现在列表首位。
- 某一步失败（菜单没出现/弹框没出现）：先关闭残留弹层（按 Esc 或点空白），再从第 1 步重试当前视频，最多重试 3 次。
- 如果连续多次异常或疑似风控（页面加载出验证/空白），停止操作冷却 1~2 分钟再继续。

## 与接口写入的关系

- GUI 流程慢（每条约数秒）但不需要处理 CSRF 令牌。
- 接口批量移动快得多，要求 CSRF 令牌 + POST（形态见 `docs/api-methodology.md`）。
- **决策**：默认走接口批量；接口持续校验失败/风控无法恢复时整体转 GUI。**接口批量必须遵守三条铁律**（批量参数不重复名、类型后缀取记录字段、批后抽干源夹验证），否则会大量静默失败。

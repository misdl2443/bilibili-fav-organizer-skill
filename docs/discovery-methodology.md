# 发现方法论（discovery-methodology）

> 本文档描述**通用黑盒观察方法论**：如何通过平台自身的页面交互与公开能力，观察其网络活动、识别数据结构、建立最小验证循环。
> **不指向任何特定平台实现，不提供任何工具名称、接口地址或操作步骤。** 读者须自行判断其使用是否符合目标平台协议与适用法律（见 `DISCLAIMER.md`）。

## 一、观察法（从页面交互到数据结构）

- **通过平台自身的页面交互观察其网络活动**：所有 Web 平台的前端都会与后端通信，浏览器提供的开发者工具（公开能力，人人可用）即可查看这些请求与响应。无需任何额外工具。
- **从请求-响应推导数据结构**：
  - 响应中的"列表"通常带分页字段（当前页 / 总数 / 是否有更多 / 游标）——注意**"是否有更多"与"本页条数"是两个独立信号**，页面条数不满不代表没有下一页；
  - 列表项通常带状态字段（如"失效/正常"），状态值变化即内容不可用；
  - 写操作（新建/删除/移动）的请求通常带一个"防伪造令牌"（CSRF 类），令牌随会话轮换、需现取现用。

## 二、特征识别模式（从响应特征推断平台行为）

| 特征 | 推断 |
|---|---|
| 返回"成功"但数据未变化 | 可能静默失败——**成功码 ≠ 生效**，需以实际数据复核 |
| 显示的条数与实际读取不一致 | 条数可能是**缓存值**，严重滞后——以逐页读空为准 |
| 批量参数同名重复 | 服务端可能只认第一个且返回成功——**参数不能重复名** |
| 请求过快返回风控码 | 平台有 IP 级限流——需限速 + 冷却 + 随机抖动 |
| 脱离页面环境直接发请求返回"未登录" | 登录态含浏览器专属 cookie（如 HttpOnly）——**写操作需在页面上下文** |

## 三、最小验证法（冒烟测试）

- **先验证最小写操作，再批量**：对一个已确认可安全撤销的最小操作（如删除一个已确认空的条目容器），先执行一次，验证"返回成功"且"实际数据确已变化"，再放大批量——避免批量后才暴露链路问题。
- **以数据复核为准，不以返回码为准**：每次写操作后，用读取接口把源数据逐页读空复核，残留即补跑，循环到清空。

## 四、双通道/降级思维

- **一种读取方式受阻时换通道**：如"页面内直接请求"被环境拦截，可改用"跳转到接口地址读取返回文本"；一种通道连续失败，自动切换另一通道，不要原地重试。
- **降级顺序**：主路径 → 减参重试（≤2 次）→ 换通道 → 兜底（GUI 页面点击由页面自身处理）。
- **断点续传**：任何批量任务结果逐条落盘，中断后重跑跳过已完成项——观察与验证都基于"可复现、可续跑"。

## 五、伦理与合规约束（必须遵守）

- 本方法论**仅限个人学习与研究**，用于理解公开可观察的 Web 平台行为。
- **不提供**：绕过平台安全机制的实现、自动化规避风控的手段、批量骚扰或侵犯隐私的能力。
- **使用者须遵守目标平台《用户协议》《开发者协议》及适用法律法规**；平台商标、接口、数据结构的知识产权归原平台。
- 以"观察平台自身的网络活动"为边界，不做逆向工程、不攻击、不干扰平台服务。

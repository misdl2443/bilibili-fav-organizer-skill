# 文本子代理分类方法论（subagent-classify）

> 定位：**兜底方案**。首选本地视觉模型（封面+标题，见 SKILL.md 阶段二）；仅当本地模型不可用、或视觉分类持续校验失败时，启用本子代理按标题+标签分类；**子代理连续卡死则主模型直接分类**。

## 子代理选型与纪律

- **模型**：便宜、快速的纯文本模型（分类只需要标题文本，无需视觉）。
- **并行切块**：每条约几十字节，每个子代理 ≤300 条（过大易不稳定），切成多份并行跑。
- 子代理只做判断，不碰浏览器、不碰网络。

### 子代理可能谎报完成（务必防）

子代理会"报告已完成并写入文件"，但**文件根本没落盘**（实测并行代理中部分如此）。所以：

- 提示词里必须要求子代理写完后用**行数统计 + 读首尾几行**自证，并把证据放进最终报告。
- 主模型合并前**必须独立校验**：对每份结果，读回文件，逐行解析，校验 aid 集合与输入完全一致、类目都在合法枚举内、行数 == 输入行数。任何一份校验失败就重跑那份，不能信子代理的口头报告。

## 输入/输出契约

- 输入文件每行：`aid<TAB>标题<TAB>标签<TAB>UP主名`（标签用逗号分隔，无标签填 `-`；标题/标签/UP主内的制表符/换行先替换成空格）。
- 输出文件每行一个 JSON：`{"aid":<原始数字aid>,"cat":"<分类名>"}`。
- **行数必须等于输入行数，aid 必须原样回传**。

## 合并回主结果（方法论步骤）

把各子代理结果文件合并进分类主结果：

1. 读主结果文件（含全部"未分类"条目）。
2. 对每份子代理结果，逐行解析出 `{aid, cat}`，建立 标识→类目 映射。
3. 遍历主结果，凡"未分类"且映射里有的条目，用子代理结果覆盖。
4. 统计：合并了多少条、剩余"未分类"多少条。
5. 合并前先跑校验（见"防谎报"节）。

## 类目设计原则

- **按用途**分类，与用户已有收藏夹风格一致（先看现有收藏夹命名再定类目，不要生造风格）。
- 类目数控制在 15~25：太少则杂、太多则碎。
- 时政/键政类标题普遍间接（玩梗），是"未分类"的最大来源，可用 UP 主定位兜底。
